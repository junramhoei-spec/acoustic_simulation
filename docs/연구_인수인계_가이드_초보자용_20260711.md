## 1. 이 연구는 무엇을 하는가 (3분 요약)

**목표: 컵(용기)에 물을 조금씩 부으면서 나는 소리만 듣고, 컵의 속 모양을 알아맞히기.**

```
물을 한 스텝(ΔV) 붓는다
   → 스피커로 소리를 쏘고 마이크로 녹음한다
   → 공기 기둥의 공명 때문에 특정 주파수에서 소리가 움푹 꺼진다(딥, dip)
   → 물이 찰수록 공기 기둥이 짧아져 딥의 위치가 옮겨간다
   → 이 "딥의 이동 패턴" 시퀀스를 신경망에 넣으면…

   신경망의 답: ① 컵 전체 높이 H (숫자 1개)
               ② 바닥부터 10mm 층마다의 반지름 r(z) (숫자 25개 = "슬롯")
```

- 실제 컵 데이터를 모으기는 힘들어서, **물리 시뮬레이터(TMM)** 로 가짜 데이터를
  대량 생성해 학습한다. (`v2/forward/tmm.py`가 그 시뮬레이터)
- 시뮬레이션으로 배운 모델을 **실제 녹음**에 적용하는 것이 다음 큰 관문이다.
  이걸 **sim-to-real(심투리얼)** 이라고 부른다.

## 2. 용어 사전 (이 프로젝트에서 실제로 쓰는 말만)

| 용어 | 뜻 |
|---|---|
| **학습(training)** | 모델에게 문제(스펙트럼)와 정답(형상)을 반복해서 보여주며 가중치를 조정하는 과정. `v2/train.py` |
| **에폭(epoch)** | 전체 학습 데이터를 한 바퀴 다 보는 것. 보통 30바퀴 돌린다 |
| **loss(손실)** | "지금 얼마나 틀렸나"의 점수. 학습은 이걸 줄이는 방향으로 진행 |
| **train/val/test 분할** | 데이터를 80/10/10으로 나눔. train=공부용 문제집, val=모의고사(학습 중 실력 확인·보정계수 산출), test=수능(마지막에 딱 한 번 채점) |
| **MAE** | 평균 절대 오차. \|예측−정답\|의 평균. **H_MAE**는 높이 오차(mm), **r_MAE**는 반지름 오차(mm). 작을수록 좋다 |
| **체크포인트(.pt)** | 특정 시점의 모델 가중치 저장 파일. `dataset/models_v2/`에 있음. `이름.pt`=종합점수 최고 시점, `이름_bestH.pt`=높이만 최고인 시점 |
| **과적합(overfitting)** | 문제집(train)만 달달 외워서 모의고사(val) 점수가 오히려 나빠지는 현상 |
| **시소 현상** | 한 모델이 H와 r을 같이 배울 때 몸통(공유 층)을 서로 뺏으며 한쪽이 좋아지면 다른 쪽이 나빠지는 것. 이 연구의 핵심 골칫거리였음 |
| **detach** | H 머리로 가는 학습 신호를 몸통에서 끊는 스위치. ON=몸통은 r 전용(H가 굶음), OFF=같이 씀(시소 위험). 실험 결과 **높이에는 OFF가 유리** |
| **continuity 손실** | "예측한 컵 모양에 실제 부은 물 부피가 들어가야 한다"는 물리 상식을 loss에 추가한 것. 일반 정규화(dropout 등)보다 과적합 억제에 훨씬 효과적이었음 |
| **H 보정(calibration)** | 모델의 높이 눈금이 일정하게 밀려 있을 때 1차식(a×예측+b)으로 펴는 것. val에서 a,b를 구함. 산포(들쭉날쭉)는 못 고침 |
| **reality gap** | 시뮬과 실측의 미묘한 차이. 시뮬 점수를 극한까지 쥐어짜면 오히려 실측에서 나빠질 수 있음 → 시뮬 최고점수가 목표가 아님 |
| **테스트타임 정제** | 학습이 끝난 뒤, 예측 하나하나를 "물리 시뮬레이터에 다시 넣어 측정과 맞을 때까지 미세 조정"하는 것. 미분가능 TMM(`tmm_torch.py`)이 필요 |
| **미분가능(differentiable)** | "출력을 이만큼 바꾸려면 입력을 어느 쪽으로 움직여야 하나"(gradient)를 자동 계산할 수 있는 형태. PyTorch로 짜면 공짜로 얻는다 |

## 3. 지금까지의 실험 결과 (2026-07-07까지, 시뮬 데이터 기준)

| 모델 | r_MAE | H_MAE(보정 후) | 한 줄 평 |
|---|---|---|---|
| CNN `base_ratio_v2` | 2.47mm | 9.13→**4.38mm** | 보정이 잘 먹음. H 기준 기록 보유자 |
| RNN detach-on `rnn_ratio` | **1.74mm** | 12.1→11.7mm | r은 최고지만 H는 산포라 보정 무력 |
| RNN detach-off `rnn_ratio_nodetach` | 2.22mm | raw 6.2mm (1에폭 시점) | 19에폭에서 중단, 보정·TEST 미산출 ← **evaluate.py로 채점하면 됨** |
| RNN+continuity `rnn_continuity` | ~1.5–1.8mm | ~11mm | 30에폭 과적합 없이 안정. **r 전문가 확정** |
| dropout/wd/lr 스윕 (`*_reg`, `d128`) | — | — | 전부 과적합. 실패 기록으로만 의미 |

**핵심 교훈 3가지**
1. 높이는 detach OFF가 유리 (보정이 먹히는 "상관 있는" 출력이 나옴)
2. 물리 기반 continuity 손실 > 일반 정규화 (과적합 억제·r 정확도 모두)
3. 선형 보정은 눈금만 펴고 산포는 못 편다

**현재 전략: 전문가 결합 + 테스트타임 정제**
```
[H 전문가: detach-off 모델] ──→ H (보정 적용)
                                    ↘
                                     (r, H) 결합 ──→ [테스트타임 정제] ──→ 최종 형상
                                    ↗                (미분가능 TMM으로
[r 전문가: rnn_continuity] ──→ r(z) 25슬롯           물리적으로 봉합)
```
시소의 근원(몸통 공유)을 모델 분리로 원천 차단하고, 둘의 물리적 불일치는
정제 단계가 자동으로 꿰맨다.

## 4. 오늘(7/11) 새로 만든 도구 3개

### ① `v2/evaluate.py` — 체크포인트 채점기
아무 .pt 파일이나 넣으면 보정계수 적합 → 보정 후 TEST 점수 + 슬롯별 r_MAE를 출력.
```
python v2\evaluate.py --ckpt dataset\models_v2\rnn_ratio_nodetach_bestH.pt --save
```
`--save`를 붙이면 보정계수를 파일 안에 기록해 두어 combine.py가 재사용한다.

### ② `v2/combine.py` — 전문가 결합기
H 전문가 + r 전문가를 한 팀으로 묶어 시뮬 테스트셋을 채점한다.
```
python v2\combine.py --h_ckpt dataset\models_v2\rnn_ratio_nodetach_bestH.pt ^
                     --r_ckpt dataset\models_v2\rnn_continuity.pt
```
성공 판정: H_MAE ≤ 4.38mm(CNN 기록)와 r_MAE ≤ ~1.8mm(continuity 기록)를 동시 달성.
실측 데이터 1개 추론용 `CombinedPredictor.predict()`도 들어 있다(링 검증 때 사용).

### ③ `v2/forward/tmm_torch.py` — 미분가능 물리 시뮬레이터
테스트타임 정제의 심장. NumPy 원본(tmm.py)과 수치 일치 검증 완료:
- 스펙트럼 오차 최대 2.3e-2 (전부 스트루브 함수 근사 기인, 딥 바닥에만 국한.
  동일 근사 조건에서 구현 차이는 1e-8 이하로 확인)
- gradient는 유한차분과 1.8e-5 수준 일치
```
python v2\forward\tmm_torch.py     ← 아무 컴퓨터에서나 자가 검증 실행
```

### 오늘 발견한 함정 2개 (같은 실수 방지용 기록)
1. **`torch.special.bessel_j0/j1`은 미분 규칙이 없다** (torch 2.13 기준).
   에러 없이 gradient가 조용히 누락된다. → tmm_torch.py에 도함수 공식
   (J₀′=−J₁, J₁′=J₀−J₁/x)을 직접 등록해 해결했다. 절대 원복하지 말 것.
2. **train.py의 `--c_weight` 기본값이 1.0** (continuity 손실 자동 ON).
   과거 nodetach 실험(7/6)은 continuity 도입 전이라, 그때와 같은 조건으로
   재학습하려면 `--c_weight 0`을 명시해야 한다.

  지워라. OneDrive 동기화가 mtime을 꼬이게 해서 파이썬이 옛날 캐시를 쓸 수 있다.

  (`python -c "import torch;print(torch.cuda.is_available())"` → True 확인).
